# PLI — интерпретатор учебного языка программирования

**PLI** (Programming Language Interpreter) — учебный императивный язык программирования с динамической типизацией и интерпретатор, написанный на C. Программы выполняются без компиляции: исходный код проходит лексический и синтаксический анализ, из него строится AST, после чего интерпретатор обходит дерево и исполняет инструкции. Язык поддерживает переменные, арифметику, логические операторы, условия `if`/`else`, циклы `while`, а также ввод и вывод через `read` и `print`. Проект реализует полный пайплайн интерпретатора — от токенизации до выполнения — с хэш-таблицей переменных, системой ошибок и собственным модулем управления памятью.

Формальная грамматика: [`syntax.ebnf`](syntax.ebnf).  
Подробное руководство по языку: [`USER_GUIDE.md`](USER_GUIDE.md).  
Источники и литература: [`REFERENCES.md`](REFERENCES.md).

## Быстрый старт

### Сборка

```bash
mkdir -p build && cd build
cmake ..
cmake --build . --target pli
```

Исполняемый файл: `build/bin/pli`.

### Запуск

**Из файла:**

```bash
./build/bin/pli examples/fact.pli
```

**Интерактивный режим** (без аргументов — ввод построчно, пустая строка завершает ввод):

```bash
./build/bin/pli
```



### Пример программы

```pli
var name = "PLI"
var version = 1

print("Hello from ", name, version)
```

Вывод:

```
Hello from PLI 1
```

## Возможности языка


| Категория          | Поддержка                                                          |
| ------------------ | ------------------------------------------------------------------ |
| Типы               | `int`, `float`, `bool`, `string`                                   |
| Переменные         | `var x = expr`, присваивание `x = expr`                            |
| Управление потоком | `if` / `else`, `while`                                             |
| Ввод-вывод         | `print(...)`, `read(var)`                                          |
| Операторы          | арифметика, сравнение, логика (`and`, `or`, `not`) с short-circuit |


**Не поддерживается:** функции, массивы, цикл `for`, комментарии, модули, работа с файлами из программы.

## Архитектура интерпретатора

```
Исходный код (.pli)
       │
       ▼
  lexer.c          ──► поток токенов
       │
       ▼
  parser.c         ──► AST (program_t)
  parse_expr.c
       │
       ▼
  executor.c       ──► выполнение
  eval_expr.c
       │
       ▼
  var.c            ──► хэш-таблица переменных (FNV-1a, open addressing)
```


| Модуль                                                    | Назначение                                      |
| --------------------------------------------------------- | ----------------------------------------------- |
| `src/lexer.c`                                             | Лексический анализ                              |
| `src/parser.c`, `src/parse_expr.c`, `src/parser_api.c`    | Рекурсивный спуск, построение AST               |
| `src/executor.c`, `src/eval_expr.c`, `src/executor_api.c` | Tree-walking интерпретация                      |
| `src/var.c`                                               | Хранение переменных                             |
| `src/ast_free.c`                                          | Освобождение AST                                |
| `src/err.c`                                               | Система ошибок, вывод при выходе через `atexit` |
| `src/memctl/mem.c`                                        | Tracking allocator для контроля памяти          |

## Сборка и режимы


| Режим                               | Команда                                                   |
| ----------------------------------- | --------------------------------------------------------- |
| Release (по умолчанию, `-O2`)       | `cmake ..`                                                |
| Debug (`-g`)                        | `cmake .. -DCMAKE_BUILD_TYPE=Debug`                       |
| Статический анализ                  | `cmake --build . --target analyze`                        |
| Библиотека `libpli` (API `get_ast`) | `cmake .. -DLIBPLI=ON && cmake --build . --target libpli` |
| Полная очистка build                | `cmake --build . --target fullclean`                      |


При сборке с `-DLIBPLI=ON` создаётся разделяемая библиотека с функцией `get_ast()` — парсинг программы в AST без выполнения (см. `#ifdef LIBPLI` в `src/main.c`).

## Тестирование

После сборки интерпретатора:

```bash
python3 run_tests.py test_parser/
python3 run_tests.py test_lexer_main/
python3 run_tests.py examples/*.pli
```

Скрипт `run_tests.py` запускает `build/bin/pli` на каждом `.pli`-файле и проверяет код возврата и отсутствие runtime-ошибок.
